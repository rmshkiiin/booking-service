# Сервис бронирования

REST API для бронирования ресурсов (переговорок, столиков, кортов). Пользователи регистрируются, смотрят свободные ресурсы и бронируют время, администратор управляет ресурсами и видит все брони. Главное правило: один ресурс нельзя забронировать двум людям на пересекающееся время.

**Стек:** Python 3.12, FastAPI, SQLAlchemy 2.0, PostgreSQL (SQLite для быстрого старта), JWT, Argon2, pytest, Docker Compose, GitHub Actions.

## Запуск

Локально, без Docker (используется SQLite):

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

Документация API откроется на http://127.0.0.1:8000/docs.

В Docker с PostgreSQL:

```bash
cp .env.example .env             # впиши свои SECRET_KEY и POSTGRES_PASSWORD
docker compose up --build
```

Тесты и линтер:

```bash
pytest
ruff check .
```

## Эндпоинты

| Метод | Путь | Кто может | Что делает |
|---|---|---|---|
| POST | /auth/register | все | регистрация |
| POST | /auth/login | все | вход, возвращает JWT |
| GET | /resources | авторизованные | список с фильтрами `min_capacity`, `free_from` + `free_to`, пагинация `limit`, `offset` |
| POST, PATCH, DELETE | /resources | admin | управление ресурсами (удаление «мягкое») |
| POST | /bookings | авторизованные | создать бронь |
| GET | /bookings | авторизованные | мои брони |
| DELETE | /bookings/{id} | владелец | отменить бронь (чужая даёт 404) |
| GET | /admin/bookings | admin | все брони и статистика |
| GET | /health | все | проверка, что сервис жив |

Администратором становится пользователь, который зарегистрируется с email из переменной `ADMIN_EMAIL`. Время передаётся в ISO 8601 и хранится в UTC.

## Как устроена бронь без пересечений

Интервалы `[start, end)` пересекаются, если `существующий.start < новый.end` и `существующий.end > новый.start`. Поэтому брони «10:00–11:00» и «11:00–12:00» совместимы. Проверка и запись идут в одной транзакции, а строка ресурса блокируется через `SELECT ... FOR UPDATE`, чтобы два одновременных запроса не создали пересекающиеся брони. Для поиска пересечений есть составной индекс `(resource_id, start_time)`.

## Структура

```
app/
  routers/     HTTP-слой: эндпоинты и коды ответов
  services/    бизнес-логика (бронирование, отмена)
  models.py    таблицы SQLAlchemy
  schemas.py   схемы запросов и ответов (pydantic)
  security.py  хеширование паролей и JWT
  deps.py      зависимости: текущий пользователь, проверка роли admin
tests/         тесты на pytest (база в памяти)
```
